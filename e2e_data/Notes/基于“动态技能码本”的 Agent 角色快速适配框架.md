## 1. 研究直觉与核心痛点 (The Intuition)

我们现在的 Agent 系统面临一个尴尬的二选一：

1. **用 System Prompt (提示词)：** 就像给模型看“剧本”。优点是改起来快，缺点是**占内存**（挤占上下文窗口）、**不稳**（对话长了容易忘设定）、**浅层**（很难通过一段文字改变模型的深层推理逻辑，比如“安全性优先”）。
    
2. **用 SFT/LoRA (微调)：** 就像给模型做“脑科手术”。优点是效果稳、理解深，缺点是**重**（切换角色需要加载权重）、**死**（训练好就定型了，没法在线调整）。
    

我们的直觉是： 能不能把“角色”变成一种外挂的插件包？

这种插件包不用很大，它只包含一些核心的**“行为原语”（比如：语气严肃、关注代码安全、使用Markdown格式）。

当我们需要一个“严厉的代码审核员”时，我们不需要重写模型，也不需要写几千字的Prompt，而是直接在模型的中间层**“挂载”这几个特定的行为原语。

## 2. 方案架构：三步走 (The Method)

我们不修改大模型（LLM）原本的参数，而是在旁边搭一个小型的控制网络。这个过程分为三步：**压缩 -> 查表 -> 干预**。

### 第一步：压缩 (The Translator)

- **问题：** 用户定义的角色描述（System Prompt）是自然语言，计算机不好直接操作。
    
- **做法：** 我们训练一个小型的编码器（Encoder）。
    
- **直观理解：** 它的作用是把一段长文本（比如“你是一个资深的Python安全专家...”）压缩成一个**极简的“角色索引向量”**。这个向量不包含具体的文字信息，只包含**意图方向**。
    

### 第二步：查表 (The Codebook)

- **问题：** 如果每个角色都生成一个全新的向量，太乱了，而且很难复用。
    
- **做法：** 我们设计一个**“行为码本” (Codebook)**。这就好比一个**“乐高积木库”**。
    
    - 积木块 A 代表“简洁输出”；
        
    - 积木块 B 代表“批判性思维”；
        
    - 积木块 C 代表“Python 语法”。
        
- **直观理解：** 上一步生成的“角色索引向量”，本质上是一个**选积木的清单**。它告诉系统：“为了扮演这个安全专家，请从库里把积木 B 和 积木 C 拿出来。”
    
- **优势：** 这种设计是**可组合的**。我们不需要单独训练一万个角色，只需要组合有限的基础积木。
    

### 第三步：干预 (The Steering)

- **问题：** 积木拿出来了，怎么影响大模型？
    
- **做法：** 我们使用**中间层干预**。
    
- **直观理解：** 大模型在思考问题时，信息是一层一层往上传递的。我们在大模型的中间层（通常是负责逻辑推理的那几层）安插一个“过滤器”。
    
    - 这个过滤器的参数，就是我们刚才选出来的“积木”。
        
    - 比如积木 B（批判性思维）被激活，它就会在中间层抑制模型“顺着用户说”的倾向，放大“找漏洞”的倾向。
        
    - 这比在输入端加 Prompt 有效得多，因为直接改了模型的“脑回路”。
        

## 3. 进化机制：越用越顺手 (The Evolution)

这是超越传统微调的关键点。

- **场景：** 用户反馈“你太啰嗦了”。
    
- **传统方法：** 只能改 Prompt，或者重新收集数据微调模型（太慢）。
    
- **我们的方法：** **修改“选积木”的策略。**
    
    - 系统接收到负反馈后，不需要改动模型参数，也不需要改动积木本身。
        
    - 它只需要更新那个**“清单生成器” (Router)**。下次再遇到类似任务，它会自动降低“详细解释”积木的权重，增加“简洁输出”积木的权重。
        
    - 这就像一个图书管理员，书（积木）没变，但他更懂读者口味了，推荐的书变准了。
        

## 4. 实验设计 (The Experiment)

为了证明这个思路靠谱，我们需要做三个核心实验：

### 实验一：角色一致性与“零Token”优势

- **目的：** 证明我不给模型看 System Prompt（省下了宝贵的上下文窗口），模型依然能扮演好角色。
    
- **做法：** 对比 **Prompting（给完整人设）** 和 **我们的方法（不给文本，只注入向量）**。
    
- **预期结果：** 我们的方法在代码生成的规范性、安全性上，能达到甚至超过 Prompting 的效果，且 Context 占用率为 **0**。
    

### 实验二：组合能力验证

- **目的：** 证明我们的“积木”是可以乱炖的。
    
- **做法：** 强制激活“严厉语气”积木 + “Python代码”积木。
    
- **预期结果：** 模型应该输出一段严厉的 Python 代码评审，而不是精神分裂（比如一会说英文一会说中文）。这证明了我们把行为**解耦**成功了。
    

### 实验三：在线进化模拟

- **目的：** 证明系统能听得懂人话并改错。
    
- **做法：** 模拟一个多轮对话，第一轮故意让模型出错（比如代码风格不对），然后给出简短反馈。
    
- **预期结果：** 传统的 LoRA 模型改不过来（因为参数死了），我们的模型能通过调整“积木权重”，在 2-3 轮内迅速修正行为。
    

## 5. 总结：一句话卖点

我们提出了一种**介于 Prompt 和 微调 之间的新范式**：它像微调一样深入改变模型行为，又像 Prompt 一样灵活轻便。通过维护一个**“可复用的行为积木库”**，我们让 Agent 能够以零 Token 的成本，像换皮肤一样毫秒级切换深度角色。
