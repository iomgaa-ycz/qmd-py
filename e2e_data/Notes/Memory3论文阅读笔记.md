该论文提出了一种新的记忆增强型LLM架构，旨在通过一个三层记忆体系来优化模型的知识存储、检索效率和训练/推理成本。

## 1. 核心理念：三层记忆体系

MemoryLLM的核心思想是：**并非所有知识都应该用同一种方式存储。** 它效仿人脑的记忆机制，为不同类型、不同使用频率的知识提供了不同的存储方案。

### 1.1 直观类比：人脑如何准备考试

为了通俗地理解这三种记忆，我们可以将其类比为学生准备考试的三种方式：

1. **死记硬背 (Implicit Memory / 模型参数)**
    
    - **类比：** 将知识刻进脑子，成为本能反应（如 "1+1=2"）。
        
    - **特点：** 写入成本极高（需要大量重复训练），但读取成本极低（张口就来）。
        
    - **适用：** 基础常识、语言模式。
        
2. **做笔记 (Explicit Memory / 显式记忆 - 论文核心创新)**
    
    - **类比：** 将重要但不常用的专业知识记在笔记本上，考试时快速翻阅。
        
    - **特点：** 写入成本中等（编码一次即可），读取成本中等（需要一次检索和Attention）。
        
    - **适用：** 专业知识、事实性数据（如法律条文、历史事件）。
        
3. **开卷考试 (External Information / RAG)**
    
    - **类比：** 考试时临时去翻厚厚的教科书。
        
    - **特点：** 写入成本为零（知识在外部），但读取成本极高（每次都要从头阅读和编码）。
        
    - **适用：** 极其生僻、偶发性的知识。
        

### 1.2 记忆的形式化定义

论文定义了一个**记忆层次 (Memory Hierarchy)**：

`Plain text (RAG) → Explicit memory → Model parameter (Implicit)`

- 从左到右：**写入成本 (Write Cost) ↑**，**读取成本 (Read Cost) ↓**
    

MemoryLLM的目标是优化总成本，即根据知识的预期使用频率 ($n_k$)，为其选择最合适的记忆格式 ($m$)，以最小化总成本：

$$\sum_{knowledge\ k} \min_{format\ m} [cost_{write}(k,m) + n_k \cdot cost_{read}(k,m)]$$

## 2. "显式记忆" (Explicit Memory) 的实现机制

论文的核心创新在于"显式记忆" (Explicit Memory)，它是一种稀疏的Attention Key-Value对。

### 2.1 关键机制(一)：如何抽取关键Token？(Token稀疏化)

显式记忆并非存储完整的知识原文，而是存储原文中**最关键的Token**的KV向量。

- **核心思想：** 选择"最容易被其他Token关注"的Token。
    
- **计算方法：** 计算每个Token的"被关注度"，即**按列求和**。
    
    - `w_j = sum_over_all_i( attention_score(token_i → token_j) )`
        
    - `w_j` 代表Token `j` 被所有其他Token（包括它自己）关注的总分量。
        
- **选择：** 每个Attention Head独立选择得分最高的Top-K个Token（论文中K=8）。
    
- **近似计算：**
    
    - 理论上应使用`softmax`后的权重，但为了加速，论文实现时直接对`exp`的结果求和，因为只关心相对排序。
        
    - `w_j ≈ sum_i( exp(Q_i · K_j^T / √d_h) )`
        
- **关键的"三不"原则：**
    
    1. **不使用 Causal Mask：** 因为编码Reference时需要理解全文，而非自回归生成。
        
    2. **不使用 RoPE 位置编码：** 让所有位置的Token有平等的机会被选中，避免位置偏见。
        
    3. **不使用温度缩放（在某些实现中）：** 仅关心相对重要性。
        
- **结果：** 不同的Head会独立选出不同的Top-8 Token，从而从不同语义角度（如Head 0关注法律条款，Head 3关注犯罪行为，Head 7关注刑罚结果）捕捉知识的精华。
    

### 2.2 关键机制(二)：稀疏KV如何集成到Transformer？

Memory3采用**直接拼接 (Concatenation)**的方式将显式记忆集成到模型中。

1. **架构设计：**
    
    - 模型共44层，**只有前半部分的22层**被设为"Memory Layers"，可以访问显式记忆。
        
    - 后22层为普通Attention层，只处理当前上下文。
        
2. **推理流程（以生成第i个Token为例）：**
    
    1. **检索 (Retrieve)：** 每处理64个Token，模型根据这64个Token的 embedding 检索（如使用FAISS）知识库，找出Top-K (如K=5) 个最相关的显式记忆 (Memories)。
        
    2. **拼接 (Concat)：** 在前22层的Memory Layers中，将检索到的Memories的KV与当前上下文 (Context) 的KV进行拼接。
        
        - `K_total = concat([K_mem_1, K_mem_2, ..., K_mem_5, K_ctx])`
            
        - `V_total = concat([V_mem_1, V_mem_2, ..., V_mem_5, V_ctx])`
            
    3. **注意力计算 (Attend)：** 模型的Query ($Q_i$) 同时对拼接后的`K_total`和`V_total`进行Attention计算。
        
    4. **后层处理：** 在后22层，模型只对`K_ctx`和`V_ctx`进行普通Attention。
        
3. **设计亮点：**
    
    - **并行位置编码：** 检索到的5个Memories都使用相同的`[0, 127]`位置编码，而不是串行（如`[0, 127]`, `[128, 255]`...），这避免了"Lost in the Middle"问题。
        
    - **BOS Token区分：** 编码Reference时使用特殊BOS (如`⟨s⟩Reference:`)，推理时也添加此BOS，让模型能区分"编码"和"推理"两种模式。
        
4. **存储压缩：**
    
    - 通过Token稀疏化 (128 -> 8) 和向量量化 (OPQ+PQ)，Memory3实现了**高达 1/1830** 的压缩比，将PB级的原始KV压缩到TB级 (4.02TB)。
        

### 2.3 关键机制(三)：显式记忆可读吗？(可解释性)

这是一个核心问题。答案是：**向量本身不可读，但具有极高的可追溯性。**

- **存储内容：** 显式记忆存储的是高维浮点数向量（如 `[0.231, -0.582, ...]`)，不是文本。
    
- **"身份证"机制：** 每一个Memory都带有一个明确的"身份证"，链接回其来源：
    
    1. `reference_id`: 来自哪篇原始文献。
        
    2. `reference_text`: 原始文献的128-token文本。
        
    3. `selected_token_indices`: 选中的Top-K Token的索引。
        
    4. `selected_tokens`: 选中的Top-K Token的原文（如 `["刑法", "234条", "故意"]`）。
        

**可解释性光谱：**

|记忆类型|可解释性|追溯能力|
|---|---|---|
|**RAG (纯文本)**|100% (完全可读)|✅ 完全透明|
|**Memory3 (稀疏KV)**|~65% (可追溯)|✅ 可追溯原文<br><br>✅ 知道关键Token<br><br>❌ 向量本身需解释|
|**Implicit (模型参数)**|~15% (黑盒)|❌ 无法定位知识来源|

因此，当模型使用Memory3回答时，我们可以清晰地展示："本答案基于文献A、B、C，并重点关注了其中的 'XX', 'YY', 'ZZ' 等关键词。" 这极大地提高了模型的透明度。

## 3. 训练与构建

### 3.1 关键问题：两阶段训练法 (Two-Stage Pretraining)

模型在训练初期权重随机，无法计算出有意义的"被关注度"，也就无法选出有意义的关键Token。这是一个"鸡生蛋"问题。

**解决方案：两阶段预训练**

1. **Stage 1: Warmup (热身阶段)**
    
    - **目标：** 让模型学会基础语言理解，使其Attention权重具有语义意义。
        
    - **方式：** **不使用**显式记忆，像普通LLM一样进行预训练。
        
    - **数据：** 训练了 **3.1T** Tokens。
        
    - **类比：** 学生在高中前打好基础，学会阅读和理解。
        
2. **Stage 2: Continual Train (持续训练阶段)**
    
    - **目标：** 学会如何读写和利用显式记忆。
        
    - **方式：** **开启**显式记忆功能，加载Warmup阶段的权重继续训练。此时模型可以抽取出有意义的关键Token来构建Memories。
        
    - **数据：** 训练了 **120B** Tokens。
        
    - **类比：** 学生上大学后，开始学习如何查阅专业文献（做笔记）来解决问题。
        

论文实验证明，如果从头（随机权重）就开始使用显式记忆，模型会因为早期Memory充满噪音而学会"忽略"它们，导致该功能永久失效。

### 3.2 模型、数据与知识库

- **是否从头训练：** 是的，论文从零开始训练。
    
- **模型大小：** **2.4B** 非Embedding参数（44层, GQA, d=3200）。
    
- **训练数据集 (Pretraining Data)：**
    
    - 总量：约 **4T** Tokens (Warmup 3.1T + Continual 120B)。
        
    - 构成：62% 英文 (RedPajama, Pile), 22.1% 中文 (Wanjuan, MNBVC), 12.8% 代码 (GitHub), 及其余SFT/合成数据。
        
- **知识库 (Reference Dataset)：**
    
    - 来源：从预训练数据中筛选出的高质量子集，如 Wikipedia、法律文本、学术书籍、高质量代码等。
        
    - 规模：**1.1亿** 个 128-token的References (总计约14B Tokens)。
        

### 3.3 训练成本估算

论文未披露具体成本，但根据模型规模和数据量估算：

- **计算量：** 约 49 PetaFLOPs-days。
    
- **时间估算：** 在 256 卡 A800 集群上，约需 **1.5 - 2 个月** (包含了重启和调试时间)。
    
- **总成本估算：** 约 **¥860万 - ¥1700万** (约 $144万 - $287万)。
    
    - _GPU租用：_ 约 ¥600万 / $106万
        
    - _人力、存储等：_ 约 ¥260万 / $38万
        

### 3.4 成本与性能亮点

- **性能：** 2.4B的Memory3在多项基准测试上，性能**超越了 Llama2-7B/13B 和 Mistral-7B** 等模型。
    
- **性价比：** Memory3的训练成本远低于同等性能的7B模型（约 ¥2000-3000万），性价比极高。
    
- **更新成本：** 最大的优势在于**知识更新**。
    
    - _传统LLM：_ 更新知识需要重新训练/微调，成本（¥100万-500万/次）。
        
    - _Memory3：_ 只需重新编码知识库，成本极低（¥5万-10万/次）。
