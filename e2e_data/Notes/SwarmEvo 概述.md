# SwarmEvo 概述

## 执行摘要

SwarmEvo 项目提出了一条有别于主流"大模型单体智能"的技术路线。该系统通过群体智能与在线进化算法的深度融合，利用大量高效的小规模 Agent（特别是 Qwen 3-14B/32B 系列），在机器学习工程基准测试（MLE-bench）中探索 SOTA 路径。

核心创新在于：系统从完全相同的初始提示词出发，通过共识主动性（Stigmergy）协作机制和基于绩效的进化算法，使 Agent 群体自动分化出专业角色。在决策层面，SwarmEvo 采用**基于对抗辩论的 3-Agent 委员会机制**，通过执行者、对抗者和综合者的辩证交互，打破同质化群体的相关性误差，实现从"平庸的大多数"到"精英专家团"的跃迁。

### 1.1 单体智能的瓶颈

当前 AI 领域由"缩放定律"主导，倾向于使用单体巨大的前沿模型解决复杂推理任务。然而在 MLE-bench 等真实工程基准测试中，单体智能体架构暴露出显著局限性：

- **探索广度受限**：前沿模型推理成本高昂且受速率限制，只能探索极窄的解空间路径
- **缺乏多样性**：受限于预训练偏好，易陷入单一策略
- **故障恢复能力差**：长周期任务中一旦产生幻觉或死循环，整个任务即告失败

目前的 SOTA 方案 AIDE（基于 OpenAI o1-preview）虽引入树搜索机制，获得约 16.9% 的奖牌率，但仍受限于其核心推理引擎的单一性和高延迟。

### 1.2 为什么选择 Qwen 3-14B/32B？

Qwen 3 系列在此时成为理想选择：

- **性能与成本的甜蜜点**：Qwen 2.5-Coder-32B 在代码生成任务上已展现出媲美 GPT-4o 的能力
- **高吞吐推理**：使用 vLLM 等推理框架，在相同算力预算下可运行 50-100 个 Qwen Agent，而只能运行 1 个 o1 Agent
- **长上下文支持**：支持 128k 甚至更长的上下文窗口，对阅读 Kaggle 文档和处理仓库级代码至关重要

## 2. 理论基础

### 2.1 共识主动性（Stigmergy）与数字信息素

借鉴生物界白蚁筑巢的无中心化协作模式，SwarmEvo 将协作机制数字化：

- **黑板系统**：包含代码、数据和元数据的共享空间
- **数字信息素**：附着在代码片段的元数据标签，高效方案的"信息素浓度"会吸引更多 Agent 基于此优化
- **衰减机制**：信息素随时间衰减，防止群体陷入局部最优

### 2.2 简单规则系统的涌现性

复杂的 MLE 行为被解构为三个原语：

- **探索（Explore）**：环境缺乏高分方案时，Agent 倾向于尝试完全不同的模型库
- **利用（Exploit）**：出现显著优于历史记录的分数时，Agent 读取该代码并微调
- **验证（Verify）**：随机抽取高分方案在不同条件下重新运行，验证鲁棒性

### 2.3 在线进化：从同质到异质

设 $P_0$ 为初始系统提示词。在时刻 $t=0$，所有 $N$ 个 Agent 都运行 $P_0$。随着任务进行，进化过程描述为：

$$P_{t+1}^{(i)} = \mathcal{M}( \mathcal{S}( {P_t^{(1)},..., P_t^{(N)}} | {S_t^{(1)},..., S_t^{(N)}} ) )$$

其中：

- $\mathcal{S}$ 是选择算子：保留高分 Agent 的提示词
- $\mathcal{M}$ 是变异算子：利用 LLM 对提示词进行随机扰动

这保证了群体在无人工干预下自动演化出适应数据集的策略组合。

### 2.4 [[核心决策机制：3-Agent 委员会架构]]
传统同质化智能体群体易陷入"算法单一文化"导致的群体迷思——所有 Agent 因共享相同预训练偏差而以高置信度犯同样错误。当多个 Agent 基于相似架构时，其错误并非独立同分布，而是表现出**高度的相关性**（Correlated Errors）。简单的投票机制无法消除系统性偏差。

**3-Agent 委员会**作为 SwarmEvo 的核心决策单元，与共识主动性、简单规则系统和在线进化机制并列，共同构成系统的理论支柱。该机制通过角色特化和对抗性提示，在系统内部制造认知多样性，迫使 Agent 跳出单一推理路径。

委员会机制将黑格尔辩证法中的"正题-反题-合题"（Thesis-Antithesis-Synthesis）映射到多智能体交互：

**正题（Thesis）—— 执行者（Worker）**

- 代表基于现有知识库的标准解决方案
- 乐观的建设者，侧重流畅性和可执行性
- 对应人类认知的"直觉系统"或"快思考"

**反题（Antithesis）—— 对抗者（Devil's Advocate）**

- 代表对正题的系统性否定
- 采用怀疑论者姿态，寻找逻辑漏洞、边缘情况及安全隐患
- 对应认知的"分析系统"或"慢思考"

**合题（Synthesis）—— 综合者（Synthesizer）**

- 通过扬弃达成更高层级的认知统一
- 具备元认知能力的仲裁者
- 权衡正反效力，生成既具执行力又经风险免疫的方案


## 3. 从同质到专业化的进化路径

### 5.1 初始状态：混沌的探索者

$T=0$ 时，50 个 Agent 拥有完全相同的 Prompt：

```
Role: MLE-Solver-v0
Mission: Solve the Kaggle competition described in competition_context.

Interaction Rules:
- Read Blackboard: Check leaderboard and task_queue
- Decide Action:
  IF (my_score < best_score * 0.8) THEN Explore
  IF (my_score >= best_score * 0.95) THEN Exploit
  IF (random < 0.1) THEN Audit
- Evolution: If fail 3 times consecutively, request "Rebirth"

Output Format: JSON with thought, code, and file_operations
```

**现象**：许多 Agent 尝试相同的基础代码 **分化触发**：黑板去重机制拒绝完全相同提交，受挫 Agent 触发微小随机扰动

### 5.2 中期阶段：角色的涌现

**特征工程专家的涌现**：

- Agent A 偶然尝试有效策略，分数大幅提升
- 行为被"信息素"强化
- 进化控制器将 Agent A 的 Prompt 作为父本衍生出 A1, A2
- 形成特征工程子群体

**调参师的涌现**：

- 另一组 Agent 发现参数微调能获得稳定低风险奖励
- 进化算法筛选出"细致、保守"特征的 Prompt
- 形成"调参师"群体

### 5.3 终局阶段：生态系统的形成

比赛末期（24小时后）演变成复杂生态系统：

- **Core Solvers (60%)**：专注于对 Top-1 方案进行集成学习
- **Explorers (20%)**：维持高变异率，尝试非主流方案突破局部最优
- **Auditors (10%)**：运行对抗性验证，检查训练/测试集分布差异
- **Debuggers (10%)**：扫描错误日志，修复库版本冲突

这种分工是任务环境压力和进化选择共同作用的结果，并非预先编码。
